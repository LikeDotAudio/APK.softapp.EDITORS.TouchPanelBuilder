# Principles — EDITORS.TouchPanelBuilder

The rules the Touch Panel Designer keeps, each with the code that keeps it.

← [Wiki home](../README.md)

| Principle | Kept by | Where it breaks |
|---|---|---|
| **Nothing names a device.** Devices and every variable they answer come from the instrument library (`<Model>.api.json`) through WEB.OsApi and from the bench (BIM / OsApi); no model, command or vendor list lives in the code. | `js/library.js` (`ControlLibrary`, `variablesFromApi`, `groupCatalogue`); `js/palettes.js` (`paletteFilter` derives "noise" from the data: `*` SCPI, readbacks of its own Sets, binary blocks) | — |
| **Unreachable is dead; an old "online" is not trusted.** A box is online only if it was heard inside the trust window (BIM's `trust_secs`, else 5 min); past that it is UNKNOWN (orange). Offline boxes stay listed, greyed, so a panel's bindings to them survive. Identity is serial / MAC / USB id / bus prefix, never an IP. | `livenessOf`, `sortBench`, `benchFromBim`, `benchDevices` (`js/library.js`); the pinned "Online & recent" section and 30 s refresh (`renderDevices`, `loadLibrary` in `js/touchPanelApp.js`); `tests/library.test.mjs` | — |
| **The glass is the real glass.** The surface is drawn at the panel's true resolution and scaled to fit; positions and sizes are panel pixels; changing the glass rescales the layout. | `fitGlass`, the preset `change` handler (`js/touchPanelApp.js`) | — |
| **Any control to anything.** Bindings are many-to-many and carry the variable's MQTT topic and the box it targets; wires are drawn live. | `bindVariable`, `drawWires`, `startPortDrag` (`js/touchPanelApp.js`); `bindingFor` (`js/library.js`) | — |
| **A copy is the whole control.** Push and hold copies type, look, behaviour, page, address and every binding; only identity and place are new. | `js/copyControl.js` (`cloneControl`, `isHold`); `tests/copyControl.test.mjs` | — |
| **Looks are hardware, not paint.** A look carries cap shape, pointer, fader cap and button style as well as colours; a vintage console previews as the controls it really had; a library look keeps the library element itself (`field`). | `STYLE_FIELDS`, `knobCap`, `faderThumb`, `buttonFace` (`js/controls.js`); `VINTAGE_LOOKS`, `lookFromField` (`js/lookLibrary.js`); `tests/looks.test.mjs` (nine distinct buttons, twenty-plus distinct hardware sets) | Vintage looks are colour approximations of the era's hardware, for theming — not reproductions of anyone's artwork. |
| **The library is read, not copied.** 969+ library looks are harvested at run time from the widget library's own frames; the Look Library's Live view draws them with the real engine. | `harvestLooks`, `loadLibraryLooks` (`js/lookLibrary.js`); `renderLiveView`, `armLiveFrame` (`js/touchPanelApp.js`) | — |
| **The device theme is the default, the control is the exception.** Blank fields in a control's Look inherit the theme. | `themeStyle`, `effectiveStyle` (`js/touchPanelApp.js`) | — |
| **What you design is what the OS runs.** A panel exports as a Gui_Frames `OcaBin` (one block per page, one field per control, absolute positions) and the same engine draws it on the glass. Export → import is exact. | `js/frameExport.js` (`panelToFrame`, `frameToPanel`); `setEngineGlass` (`js/touchPanelApp.js`); `tests/frameExport.test.mjs` | Needs WEB.Frontend-Assets ≥ a61871c8 for absolute placement; an older engine falls back to the 20 px grid written beside it. |
| **A device that has a GUI has a touch panel.** A box's presented panel (or its api.json) is its starting panel; its saved panel is kept retained on the bus. | `js/devicePanel.js`, `js/savedPanel.js` (ROAD-3503) | — |
| **The touch pad sends what the frame would.** `run.html` (opened by the Online badge on the Discovery Engine) keeps each control's own `komand_handler` and fires it the way KOMAND expects: `<topic>/config` with the handler, then `<topic>` with `{value}`, never retained; a press sends `true` then `false`. A read with no readback of its own listens on `<box>/Reading/<command>`. Nothing read yet shows `—`, never a sample value. | `js/runPanel.js` (`fireMessages`, `handlerFor`, `readbackOf`); `js/runner.js`; `tests/runPanel.test.mjs` | Outside the OS shell the portal carries no `/mqtt`: the broker comes from `config/discovered.json` `broker_urls`. |
| **One client for the CAD and the bus.** Blocks go in and out over `cad.like.audio/host@1` through the vendored APKSoftapp; standalone, Save downloads. | `js/touchPanelHost.js`; `vendor/apk-softapp/` | — |
| **No build, no dependencies.** | `package.json` (only `"test"`), plain ES modules | — |
